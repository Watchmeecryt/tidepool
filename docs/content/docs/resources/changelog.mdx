## 2026-10-30 · Tidepool App: balances in the token picker

- **Fix:** the **Exchange from/to** list now shows your balance for every token as soon as you pick a network (or **All networks**), not only for the token you already selected. Tokens you hold are listed first, and a short placeholder shows while balances load.
- **All wallets:** works for the connected wallet on NEAR, Ethereum, Base, Arbitrum, Solana, Stellar, Sui, Bitcoin and XRP Ledger. Networks without a connected wallet show no balance, and a network that can't be read shows a dash.
- **Fast:** each network is read in one batched call, in parallel, and cached for 30 seconds, so switching tabs back and forth does not refetch.

## 2026-10-30 · Tidepool App: friendlier errors and guards

- **Stellar trustlines:** when the recipient has no trustline for the output asset (USDC or USDT), the app says so as soon as the address is entered and offers an **Add trustline** button that signs a `changeTrust` with Freighter on testnet. Confirm stays disabled until it is in place.
- **Faucet:** errors show as a short callout. For an unfunded Stellar account, **Fund with Friendbot** funds it from the app and retries, and **Add trustlines** adds the test USDC and USDT trustlines through Freighter.
- **SOL payouts:** when a quote fails because the payout is under Solana's rent-exempt minimum or over the 0.005 SOL cap, the app shows the valid range in your source token with **Use minimum**, and **Try again** re-requests the quote.
- **Balance check:** with a wallet connected, a swap larger than its balance shows **Insufficient balance** with a link to the faucet. Pay from another wallet, or use the manual deposit address, still works.
- **After a redeploy** the app reloads once on its own if it asks for an old script file, and keeps your swap inputs.
- **Fix:** the amount boxes no longer jump while a quote loads.

## 2026-10-30 · Tidepool App: wallet connect on every chain

- **One-click deposit from a wallet** in the [Tidepool App](https://app.usetidepool.tech), on each testnet: Solana devnet (Phantom, Solflare, Backpack), Sui testnet (Slush / Sui Wallet, Suiet), Stellar testnet (Freighter, with the quote's memo), Bitcoin testnet4 (Xverse, Unisat, Leather) and XRP Ledger testnet (Crossmark, GemWallet, with the quote's destination tag). EVM and NEAR wallets work as before.

- **Right network only:** each connector refuses to send unless the wallet is on that chain's testnet (Solana is signed in the wallet and broadcast to devnet by the app; Bitcoin never falls back to testnet3). Otherwise the app says what to switch.
- **Manual deposit still works** on every chain: send to the deposit address with the memo or destination tag shown, from any wallet. Per-swap caps are unchanged.
- **Fix:** the current step of the swap status tracker no longer shows a browser focus rectangle, only the orange ring.

## 2026-10-30 · Tidepool App: a web UI for swaps and bridges

- **New:** [app.usetidepool.tech](https://app.usetidepool.tech), a browser app for the testnet, labelled as the testnet version of NEAR Intents with 1Click-compatible APIs. It is a static client of this public API (`/v0/tokens`, `/v0/quote`, `/v0/deposit/submit`, `/v0/status`, `/v0/faucet`) and needs no backend changes.
- **Flow:** token and network picker for every asset in `/v0/tokens` (respecting the per-swap caps), live `EXACT_INPUT` quote (rate, minimum received, fee, deadline), recipient and refund validation per chain, deposit address with QR, memo or destination tag and a countdown, live status (`PENDING_DEPOSIT` → `KNOWN_DEPOSIT_TX` → `PROCESSING` → `SUCCESS` / `REFUNDED` / `FAILED`) with explorer links for every transaction, local swap history, and a faucet page.
- **Wallets (optional):** see the wallets entry above. Every chain also keeps the manual deposit address, QR and memo or destination tag.
- Tested end to end through the app: NEAR → Base Sepolia, NEAR → Solana devnet and NEAR → Sui testnet all reached `SUCCESS`.

## 2026-10-29 · Bitcoin watcher rate limits, payout driver hardening

- **Bitcoin testnet4 reads.** Public Esplora hosts were answering `429` to Tidepool's server, which stalled deposits (health reported `btc.ok: false`). The watcher now caches reads and shares in-flight requests, polls each deposit address every 20 seconds (2 minutes after its quote expired), backs endpoints off exponentially (honouring `Retry-After`) and also fails over to mempool.ninja. Swaps that were waiting resume on their own; a deposit that arrived after its deadline is refunded to `refundTo`.
- **No more duplicate payouts.** A concurrent-step bug could sign two transactions for one payout slot (seen on the XRP Ledger testnet bridge, where one swap was paid four times from the treasury). Every payout, sweep and refund driver (Bitcoin, Stellar, Sui, Solana, XRP) now runs one step at a time per slot, and Stellar no longer re-signs on `tx_bad_seq`. Covered by regression tests.

Why: the relayer's SOL comes from rate-limited devnet airdrops, so a small cap protects the treasury. The minimum SOL leg is 0.00089088 SOL (rent-exempt minimum). `ANY_INPUT` to a SOL recipient is rejected. Overpayment of your own deposit is returned in full and is not blocked by the cap. USDC and USDT are not capped.

The server tops the treasury up with devnet airdrops (`requestAirdrop`, never the web faucet) when it falls below 3 SOL, with backoff. The public devnet RPC faucet is currently closed, so a provider endpoint with a devnet faucet is needed to fund SOL.
- **Limits:** devnet resets wipe balances (the mint keypairs are kept so the same addresses can be re-created), rent minimums apply, associated token accounts are created for payouts, classic SPL only (no Token-2022).

## 2026-10-28 · Opt-in swap failure simulation (`simulate`)

- **New:** `POST /v0/quote` accepts an optional, Tidepool-only `simulate` field: `"STUCK"` or `"FAILED"`. Testnet only. Real 1Click has no such field, so remove it when you move to mainnet 1Click. Omit it for a normal swap. Other values return the usual helpful 400 (`message`, `hint`, `field`, `docs`, `exampleRequest`).
- `STUCK`: after the deposit is detected the swap goes `PROCESSING` and never settles. At the quote `deadline` the origin token is refunded to `refundTo` and the swap ends `REFUNDED` with `refundReason: DEADLINE_PASSED` ([refund tx](https://testnet.nearblocks.io/txns/FGasLbPb1ZCFzTZaYgxvfycmyDi1qM37UgyzqyxELFYe)).
- `FAILED`: after the deposit the swap goes `PROCESSING`, then `FAILED` about 10 s later, and the deposit is refunded with `refundReason: SWAP_FAILED` ([refund tx](https://testnet.nearblocks.io/txns/7rSC9oJacoXxAe5qberk5pN7GsZQwh5uVyCvbwM3GjAG)). Normal `FAILED` stays reserved for a refund that could not be completed.
- The flag is stored with the quote and shown in `/v0/status` only as `tidepool.simulate` (plus `tidepool.note`). Status values and `swapDetails` fields stay exactly the 1Click ones.
- It reproduces what a client sees when 1Click is slow or down, not the cause, which is inside NEAR's own infrastructure. Real status JSON for both modes is in [Testing failure cases](/docs/guides/failure-cases#stuck-or-failed-swap-simulated-outage). `examples/failure-cases.mjs` gained `stuck` and `failed` cases.

## 2026-10-27 · Settlement distinction: mainnet 1Click is confidential-only

- NEAR [rolled out 1Click swaps as confidential only](https://docs.near-intents.org/changelog/entries/2026-10-27-1click-confidential.md) on mainnet: the API shape is unchanged, the swap settles on the NEAR Private Shard with no public hash, and `swapDetails.nearTxHashes` lists only the public shield and unshield transactions.
- Tidepool's API is unchanged. Testnet swaps settle publicly on the testnet verifier, so `nearTxHashes` includes the swap's own hash; `confidentiality` stays accepted and ignored. This is not a choice by Tidepool: confidential settlement (NEAR Private Shard / Confidential Intents) runs on NEAR's private infrastructure, which isn't exposed to outside builders.
- Rely on `status` (`SUCCESS` means delivered), not on the presence of a swap hash, so your code works on both. Notes added to [Compatibility](/docs/resources/compatibility), [Status lifecycle](/docs/concepts/status-lifecycle), [`/v0/status`](/docs/api-reference/get-execution-status), [`/v0/deposit/submit`](/docs/api-reference/submit-deposit-tx), Quickstart, Roadmap, Mainnet migration and `AGENTS.md`.
