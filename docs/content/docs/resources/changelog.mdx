## 2026-10-28 · Solana devnet bridge (SOL, USDC, USDT), capped at 0.005 SOL

- **New chain:** Solana devnet, `blockchain: "sol"`, a trusted-relayer bridge run by Tidepool. Devnet only, custodial and testnet-only: the tokens have no value. Guide: [Solana devnet bridge](/docs/guides/bridge-solana-devnet). The route is listed in `/v0/tokens` and `/v0/health` (`bridges.chains.sol`) only while it is live.
- **Assets:** native SOL `nep141:sol.tp-omft.testnet` (9 decimals), and Tidepool's own classic-SPL test USDC and USDT (6 decimals): `nep141:sol-d48c1adc423a64867ac91ed2e1c0df76da323235.tp-omft.testnet` (mint `7pafEGXSmR35rLKNaD6inpfLYuEnRX9DyBc1c7M8r4Xr`) and `nep141:sol-4c5179da74eb695eb57e01b787c4937157cf2833.tp-omft.testnet` (mint `H9ERDhrU8KDeXkMna2Lw6hYJT3LSyhvypiktDc6zmoeJ`). The relayer `BEijzwSQpWxbgQQ5NfBePxUzHgLoc2vrApPe8G4St55Q` is the mint authority. `contractAddress` carries the base58 mint.
- **Deposits:** every live quote gets a unique base58 deposit address (an ed25519 key derived from the quote id and the server master seed; no on-chain program). SOL goes to the address, SPL tokens to its associated token account. Send the transfer, then `POST /v0/deposit/submit` with the signature.
- **Sweep and mint:** the deposit key signs a sweep into the treasury, the relayer pays the fee, then the matching NEP-141 is minted and credited to the verifier with `ft_transfer_call`. Credit happens at `confirmed` commitment.
- **Payouts and refunds:** the verifier withdraws the bridged token to the relayer, which creates the recipient's associated token account if needed and pays out (`transferChecked`, `mintTo` if the treasury is short, or a system transfer for SOL). Transactions are signed first, the signature is recorded, then sent, and the signature status is checked before any re-sign, so a payout cannot be paid twice. Refunds go back to `refundTo` with the same machinery.
- **The cap:** SOL is capped at **0.005 SOL (5,000,000 lamports) per swap, payout or refund**, enforced at quote time with a `400`. Why: the relayer's SOL comes from rate-limited devnet airdrops, so a small cap protects the treasury. The minimum SOL leg is 0.00089088 SOL (rent-exempt minimum). `ANY_INPUT` to a SOL recipient is rejected. Overpayment of your own deposit is returned in full and is not blocked by the cap. USDC and USDT are not capped.
- **Faucet:** `POST /v0/faucet {"chain":"sol","address":"…"}` drips test USDC and USDT (not SOL).
- **RPC and failover:** the relayer reads `SOLANA_DEVNET_RPC` first and falls back to `https://api.devnet.solana.com`; reads are batched with `getMultipleAccounts`. The server tops the treasury up with devnet airdrops (`requestAirdrop`, never the web faucet) when it falls below 3 SOL, with backoff. The public devnet RPC faucet is currently closed, so a provider endpoint with a devnet faucet is needed to fund SOL.
- **Limits:** devnet resets wipe balances (the mint keypairs are kept so the same addresses can be re-created), rent minimums apply, associated token accounts are created for payouts, classic SPL only (no Token-2022).
- **Mainnet 1Click mapping:** same fields and asset id rule, `nep141:sol.omft.near`, `nep141:sol-5ce3bf3a31af18be40ba30f721101b4341690186.omft.near` (USDC) and `nep141:sol-c800a4bd850783ccb82c2b2c7e84175443606352.omft.near` (USDT). Mainnet has no cap.
- **Verified on devnet** (2026-10-28): SOL → NEAR USDC ([Solana tx](https://explorer.solana.com/tx/2m9pQEZs5bvd6iYDdDxADz9kqv641RBkUerNJsT9sDDmjGJfuHqjzsMxxwFpapZFc4hNjTcgyy8YFcnf51DwpfsX?cluster=devnet)), NEAR USDC → Solana USDC payout ([Solana tx](https://explorer.solana.com/tx/kPW2EvGVSFeELMCgV7M6F6vLxtH8fhapRntn4gyuDgSapv5qfirccvveFWKN23muW1tPEGhSoDxSPQgTBVFP4Z9?cluster=devnet)), a `PARTIAL_DEPOSIT` refund ([Solana refund tx](https://explorer.solana.com/tx/2cKPTuCKHw5uFgkXJXCi9tUrSax75LMrDBJQpEET1qd1LzoNb7UfwhRenxXFnCyLStkZDmJUMWScMPp5NbZtWYc7?cluster=devnet)), and a 0.006 SOL quote rejected with `400`. Details and NEAR links in the [guide](/docs/guides/bridge-solana-devnet#verified-flows).
- New example `sol-deposit.ts` in tidepool-examples, `scripts/sol-airdrop-topup.mjs` (idempotent treasury top-up) and `scripts/bridge-solana-bootstrap.mjs`.

## 2026-10-28 · Opt-in swap failure simulation (`simulate`)

- **New:** `POST /v0/quote` accepts an optional, Tidepool-only `simulate` field: `"STUCK"` or `"FAILED"`. Testnet only. Real 1Click has no such field, so remove it when you move to mainnet 1Click. Omit it for a normal swap. Other values return the usual helpful 400 (`message`, `hint`, `field`, `docs`, `exampleRequest`).
- `STUCK`: after the deposit is detected the swap goes `PROCESSING` and never settles. At the quote `deadline` the origin token is refunded to `refundTo` and the swap ends `REFUNDED` with `refundReason: DEADLINE_PASSED` ([refund tx](https://testnet.nearblocks.io/txns/FGasLbPb1ZCFzTZaYgxvfycmyDi1qM37UgyzqyxELFYe)).
- `FAILED`: after the deposit the swap goes `PROCESSING`, then `FAILED` about 10 s later, and the deposit is refunded with `refundReason: SWAP_FAILED` ([refund tx](https://testnet.nearblocks.io/txns/7rSC9oJacoXxAe5qberk5pN7GsZQwh5uVyCvbwM3GjAG)). Normal `FAILED` stays reserved for a refund that could not be completed.
- The flag is stored with the quote and shown in `/v0/status` only as `tidepool.simulate` (plus `tidepool.note`). Status values and `swapDetails` fields stay exactly the 1Click ones.
- It reproduces what a client sees when 1Click is slow or down, not the cause, which is inside NEAR's own infrastructure. Real status JSON for both modes is in [Testing failure cases](/docs/guides/failure-cases#stuck-or-failed-swap-simulated-outage). `examples/failure-cases.mjs` gained `stuck` and `failed` cases.

## 2026-10-27 · Settlement distinction: mainnet 1Click is confidential-only

- NEAR [rolled out 1Click swaps as confidential only](https://docs.near-intents.org/changelog/entries/2026-10-27-1click-confidential.md) on mainnet: the API shape is unchanged, the swap settles on the NEAR Private Shard with no public hash, and `swapDetails.nearTxHashes` lists only the public shield and unshield transactions.
- Tidepool's API is unchanged. Testnet swaps settle publicly on the testnet verifier, so `nearTxHashes` includes the swap's own hash; `confidentiality` stays accepted and ignored. This is not a choice by Tidepool: confidential settlement (NEAR Private Shard / Confidential Intents) runs on NEAR's private infrastructure, which isn't exposed to outside builders.
- Rely on `status` (`SUCCESS` means delivered), not on the presence of a swap hash, so your code works on both. Notes added to [Compatibility](/docs/resources/compatibility), [Status lifecycle](/docs/concepts/status-lifecycle), [`/v0/status`](/docs/api-reference/get-execution-status), [`/v0/deposit/submit`](/docs/api-reference/submit-deposit-tx), Quickstart, Roadmap, Mainnet migration and `AGENTS.md`.
- Clarified that the `confidentiality` parameter (accepted and ignored) is separate from the `CONFIDENTIAL_INTENTS` deposit, refund and recipient types (not supported, `POST /v0/quote` returns 400), and linked NEAR's update from every page that mentions confidentiality, plus `llms.txt`.

## 2026-10-27 · No sign-up, no API key

- Clarified on the landing page, Introduction, Quickstart, `llms.txt` and `AGENTS.md`: No sign-up, no API key. Call the API directly; any `X-API-Key` or `Bearer` value is accepted (it just selects the lower fee tier). Only `/v0/account/*` needs a token, which you get instantly by signing a message with your own wallet via `POST /v0/auth/authenticate`. It only ever shows that wallet's own data.

## 2026-10-27 · Signed intents, orders, appFees, ANY_INPUT, auth, MEMO

- **New:** [`/v0/generate-intent`](/docs/api-reference/generate-intent) and [`/v0/submit-intent`](/docs/api-reference/submit-intent). Fund an `INTENTS` quote with a signed NEP-413 transfer ([submit tx](https://testnet.nearblocks.io/txns/CstqKiww5T6pAWrnX8wYuYaH2BrCL1oMnvsbbDidpC5W)).
- **New:** limit [orders](/docs/api-reference/create-order) (`/v0/orders`, JSON:API) ([fill payout](https://testnet.nearblocks.io/txns/4SBBksycbKuGHT2VcKJeeYjE3bbjWmiWmkxPZovWzZTH)).
- **New:** `appFees` on `/v0/quote`. Fees are paid in the same `execute_intents` call as the swap ([tx](https://testnet.nearblocks.io/txns/EpWHKRHMp9DTyexewL5ECoMikHvG3LLLdj3YZjnHuETJ)).
- **New:** `ANY_INPUT` swaps and [`/v0/any-input/withdrawals`](/docs/api-reference/get-any-input-quote-withdrawals).
- **New:** free JWTs via [`/v0/auth/*`](/docs/api-reference/authenticate), and [`/v0/account/*`](/docs/api-reference/get-balances).
- **New:** `depositMode: MEMO` for NEAR-native `ORIGIN_CHAIN` deposits ([memo deposit](https://testnet.nearblocks.io/txns/DPtbS93K5HMsf6LFVDvkYFVr9bFWhkjW2Qu1uobamXjt)).
- `confidentiality` stays accepted and ignored. Examples for every feature are in [tidepool-examples](https://github.com/zer0plugyut-afk/tidepool-examples).

- New [Compatibility](/docs/resources/compatibility) page: same as mainnet 1Click, different, and not supported yet.

## 2026-10-26 · NEAR RPC failover

- The server now fails over between NEAR testnet RPC providers (FastNEAR → dRPC → Intea → rpc.testnet.near.org) on rate limits (429), 5xx, timeouts and network errors, with a short cooldown for rate-limited providers. Configure with `NEAR_RPC_URLS` (comma separated); `NEAR_RPC` still sets the first provider. Signed transactions are re-broadcast unchanged, never re-signed, so retries are safe.

## 2026-10-26 · Refund USD values fixed

- `depositedAmountUsd` / `refundedAmountUsd` in `/v0/status` are no longer `"0.0000"` on refunded swaps (NEAR-only and bridged). They now fall back to the quote's unit prices. Covered by new tests (`npm test` in `server/`).
- Late-deposit (`DEADLINE_PASSED`) refunds verified end to end on Arbitrum Sepolia ([refund tx](https://sepolia.arbiscan.io/tx/0xbd81881bdf388df29eec3a339de124cd101b40f7f76efd2dd8e32258a55727ba)) and Ethereum Sepolia ([refund tx](https://sepolia.etherscan.io/tx/0xc7e2c3d7eef119bd333dd86f6d76d495b064226e7f57257246bca16e3edba1df)).

## 2026-10-26 · Test bridges to Base Sepolia, Arbitrum Sepolia and Ethereum Sepolia

- Cross-chain swaps between NEAR testnet and three EVM testnets, shaped like 1Click mainnet: `0x` deposit addresses in `/v0/quote`, bridged USDC and USDT in `/v0/tokens` with ids like `nep141:base-0x….tp-omft.testnet`, status through to `SUCCESS`, and refunds paid back on the origin chain.
- **Trusted relayer, testnet only.** The bridges are run by Tidepool as its own testnet service. A relayer watches EVM deposits, credits the matching NEP-141 into the verifier with a normal `ft_transfer_call`, and pays withdrawals back from a vault contract on each chain. See [Test bridges](/docs/guides/bridges) for what you trust.
- New per-route guides with contract addresses and tested round trips: [Base Sepolia](/docs/guides/bridge-base-sepolia), [Arbitrum Sepolia](/docs/guides/bridge-arbitrum-sepolia) and [Ethereum Sepolia](/docs/guides/bridge-ethereum-sepolia).
- The faucet accepts `{"chain":"base"|"arb"|"eth","address":"0x…"}` and mints test USDC and USDT on that chain. Gas is not included.
- `examples/swap.mjs` takes `FROM_CHAIN`, `TO_CHAIN` and `RECIPIENT`. The [SDK guide](/docs/guides/sdk) shows a cross-chain quote.
- NEAR-only flows are unchanged. EVM transaction hashes are no longer listed in `nearTxHashes`.
- The [Roadmap](/docs/resources/roadmap) moves test bridges from Planned to Shipped.

## 2026-10-25 · New theme, light and dark modes, and a demo video

- The site and docs now use the same colours as NEAR Private OTC, in light and dark. Light mode has a cream background, ink text and a bronze accent. Dark mode has a warm charcoal background, cream text and a gold accent. The font is Geist, with Geist Mono for code. - A new narrated demo video, recorded on the new theme, is on the [Introduction](/docs) page. It is served from `/videos/tidepool-demo.mp4` and supports range requests, so you can seek in it.
