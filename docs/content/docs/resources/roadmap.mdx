title: Roadmap
description: 1Click features Tidepool does not have yet, what is planned once v1 sees traction, and what is not planned.
---

Tidepool v1 covers the core 1Click swap loop on NEAR testnet: `EXACT_INPUT`, `EXACT_OUTPUT` and `FLEX_INPUT` quotes, `ORIGIN_CHAIN` and `INTENTS` deposits, status, refunds and the faucet. The features below exist on 1Click mainnet but **not** on Tidepool today. Requests that use them return 400 or 404.

<Callout title="Planned, pending v1 traction">
Nothing on this page is being built yet. Work starts once v1 has real usage. If you need one of these features, say so. Demand decides the order.
</Callout>

## Planned

| Feature | What it is | Status today | Notes |
| --- | --- | --- | --- |
| `appFees` | App fee splits: route a share of each swap to your fee recipient(s), in basis points | 400 | Mirrors 1Click's `appFees` array on `/v0/quote`. |
| `ANY_INPUT` swap type | Collect any number of deposits and convert them to one destination asset | 400 | Needs streaming deposits. See [Swap types](/docs/concepts/swap-types). |
| `depositMode: MEMO` | A shared deposit address plus a memo, instead of a unique address per quote | 400 | Lands with multi-chain support, since it only matters on chains that use memos. See [Deposits](/docs/concepts/deposits). |
| Test bridges for Base Sepolia and Ethereum Sepolia | Swap between NEAR testnet and EVM testnets, with `ORIGIN_CHAIN` deposits on Sepolia chains | NEAR only (`blockchain: "near"`) | The first step toward multi-chain. |
| `/v0/auth`-compatible endpoints | Auth routes shaped like 1Click's, so SDK code that calls them works unchanged | 404 | Mainly for SDK parity. Keys stay optional, and any `X-API-Key` or Bearer token keeps working. |

## Not planned

| Feature | Why |
| --- | --- |
| `CONFIDENTIAL_INTENTS` (deposit, refund and recipient type) | It depends on NEAR's private Confidential Intents infrastructure, which is not available on testnet. Test it on mainnet with small amounts. See [Mainnet migration](/docs/guides/mainnet-migration). |

## Until then

Use mainnet with small amounts to test these features. The [Mainnet migration](/docs/guides/mainnet-migration) guide lists what changes. Shipped work is recorded in the [Changelog](/docs/resources/changelog).
