<Callout type="success" title="No sign-up, no API key">
No sign-up, no API key. Call the API directly; any `X-API-Key` or `Bearer` value is accepted (it just selects the lower fee tier). Only `/v0/account/*` needs a real token (`/v0/orders` needs a token or any `X-API-Key` value), which you get instantly by signing a message with your own wallet via `POST /v0/auth/authenticate`. It only ever shows that wallet's own data.
</Callout>

<Callout title="Using a coding agent (Cursor, Claude Code, Codex)?">
Paste the **[dev prompt](/docs/guides/agents#prompt-snippet)** into your agent, or point it at [`/llms-full.txt`](/llms-full.txt). Prefer runnable code? Clone **[tidepool-examples](https://github.com/zer0plugyut-afk/tidepool-examples)** and run `npm run first-swap`.
</Callout>

<Callout type="warn">Community-operated testnet. Tidepool runs the maker and derives deposit-address keys. Never send real assets.</Callout>

Tidepool speaks the 1Click Swap API (OpenAPI v0.1.10) shape on NEAR testnet. If you already have a 1Click client, change its base URL to `https://www.usetidepool.tech` and use the testnet asset ids from `/v0/tokens`.

<Steps>
<Step>

### List tokens

```bash
curl https://www.usetidepool.tech/v0/tokens
```

Each token has an `assetId` such as `nep141:usdc.tidepool-sandbox.testnet`, a `decimals` value and a live USD `price`. Use those ids in quotes.

</Step>
<Step>

### Ask for a dry quote

A dry quote prices the swap without creating a deposit address or committing the maker.

```bash
curl -X POST https://www.usetidepool.tech/v0/quote \
  -H 'content-type: application/json' \
  -d '{
    "dry": true,
    "swapType": "EXACT_INPUT",
    "slippageTolerance": 100,
    "originAsset": "nep141:usdc.tidepool-sandbox.testnet",
    "depositType": "INTENTS",
    "destinationAsset": "nep141:wnear.tidepool-sandbox.testnet",
    "amount": "10000000",
    "refundTo": "alice.testnet",
    "refundType": "INTENTS",
    "recipient": "alice.testnet",
    "recipientType": "DESTINATION_CHAIN",
    "deadline": "2030-01-01T00:00:00.000Z"
  }'
```

`amount` is in base units (USDC has 6 decimals, so `10000000` is 10 USDC). `slippageTolerance` is in basis points (100 = 1%).

</Step>
<Step>

### Go live

Send the same request with `"dry": false` and a deadline a few minutes ahead. The response's `quote.depositAddress` is a fresh address used by this quote only (a NEAR account for NEAR tokens; an address on the origin chain for bridged tokens, except Stellar and XRP Ledger, which use a shared address plus a memo). Deposit `quote.amountIn` of the origin token to it ([how](/docs/concepts/deposits)), then poll:

```bash
curl "https://www.usetidepool.tech/v0/status?depositAddress=<depositAddress>"
```

</Step>
</Steps>

## Auth and fees

Auth is optional. Any `X-API-Key` header or `Authorization: Bearer <token>` value is accepted, so a dummy JWT works. A key selects the lower fee tier, as it does on mainnet 1Click:

| Pair | No key | Any key |
| --- | --- | --- |
| Most pairs | 45 bps | 20 bps |
| Stable to stable (USDC/USDT) | 26 bps | 1 bp |

## Differences from mainnet 1Click

- Tokens are Tidepool test tokens with no value. Most live on NEAR testnet (`blockchain: "near"`). Test USDC and USDT also exist on Base Sepolia (`base`), Arbitrum Sepolia (`arb`), Ethereum Sepolia (`eth`), Solana devnet (`sol`), Stellar testnet (`stellar`) and Sui testnet (`sui`), and the three native tokens SOL, XLM and SUI exist on their own chains, all through Tidepool's [test bridges](/docs/guides/bridges), a trusted relayer run by Tidepool on testnets only.
- Supported: `EXACT_INPUT`, `EXACT_OUTPUT`, `FLEX_INPUT`, `ANY_INPUT`; `appFees`; `depositMode` `SIMPLE` and `MEMO` (MEMO for NEAR-native, Stellar and XRP `ORIGIN_CHAIN` deposits only; Stellar and XRP require it); deposit and refund types `ORIGIN_CHAIN` and `INTENTS`; recipient types `DESTINATION_CHAIN` and `INTENTS`; signed intents (`/v0/generate-intent`, `/v0/submit-intent`), limit orders (`/v0/orders`), free JWTs (`/v0/auth/*`) and `/v0/account/*`.
- Confidentiality: the `confidentiality` quote parameter is accepted and ignored, so every swap settles publicly on the testnet verifier and `swapDetails.nearTxHashes` includes the swap's own hash. The `CONFIDENTIAL_INTENTS` deposit, refund and recipient types are a separate thing: they are not supported and `POST /v0/quote` returns 400. On mainnet, 1Click now settles every swap confidentially and `nearTxHashes` lists only the shield and unshield transactions ([NEAR's Oct 27, 2026 update](https://docs.near-intents.org/changelog/entries/2026-10-27-1click-confidential.md)). Confidential settlement runs on NEAR's private infrastructure, which isn't exposed to outside builders. Rely on `status`, not on a swap hash. See the [Compatibility](/docs/resources/compatibility) page.
- One maker (Tidepool's) fills every quote. There is no solver competition.
- The quote `signature` is Tidepool's maker key over the quote body, not 1Click's.
