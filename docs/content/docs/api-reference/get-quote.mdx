<p><span className="tp-method tp-post">POST</span><code>{"/v0/quote"}</code></p>

Returns **HTTP 200** on success, as 1Click does. The request below sets **every** field Tidepool accepts (the twelve required ones plus all optional ones); `simulate` is left out because it changes the swap's outcome. The response is a real dry quote. With `dry: false` the response adds `quote.depositAddress`, `deadline` and `timeWhenInactive`, see the live example below. See [Quotes and pricing](/docs/concepts/quotes) and [Swap types](/docs/concepts/swap-types) (full requests and responses for each swap type). Tidepool-only: the optional `simulate` field (`STUCK` or `FAILED`) simulates a stuck or failed swap on testnet, see [Stuck or failed swap](/docs/guides/failure-cases#stuck-or-failed-swap-simulated-outage). Remove it when you move to mainnet 1Click.

Generates a swap quote based on input parameters such as the assets, amount, slippage tolerance, and recipient/refund information. Returns pricing details, estimated time, and a unique **deposit address** to which tokens must be transferred to initiate the swap. You can set the `dry` parameter to `true` to simulate the quote request **without generating a deposit address** or initiating the swap process. This is useful for previewing swap parameters or validating input data without committing to an actual swap. This endpoint is the first required step in the swap process. Tidepool supports EXACT_INPUT, EXACT_OUTPUT, FLEX_INPUT and ANY_INPUT; appFees; depositMode SIMPLE and MEMO (MEMO for NEAR-native ORIGIN_CHAIN only); ORIGIN_CHAIN and INTENTS deposit/refund types; DESTINATION_CHAIN and INTENTS recipient types. CONFIDENTIAL_INTENTS / confidentiality is accepted but ignored. Tidepool-only: the optional `simulate` field (`STUCK` or `FAILED`) simulates a stuck or failed swap on testnet; see the Testing failure cases guide. Native ETH on Ethereum, Base and Arbitrum Sepolia (nep141:eth.tp-omft.testnet, nep141:base.tp-omft.testnet, nep141:arb.tp-omft.testnet, like 1Click's nep141:eth.omft.near, base.omft.near, arb.omft.near) is capped at 0.006 ETH (6000000000000000 wei) per swap, payout or refund: a larger ETH leg answers 400 at quote time, and payouts answer 503 while the treasury is low. ORIGIN_CHAIN deposits use a per-quote derived EOA; ANY_INPUT is rejected for native ETH origin and for DESTINATION_CHAIN ETH payouts.

**Operation id:** `getQuote` · **Auth:** optional (`X-API-Key` or `Authorization: Bearer`, any value)

### Body

| --- | --- | --- | --- |
| `dry` | boolean | yes | Flag indicating whether this is a dry run request. If `true`, the response will **NOT** contain the following fields: - `depositAddress` - `timeWhenInactive` - `deadline` |
| `depositMode` | "SIMPLE" \\| "MEMO" |  | What deposit address mode you will get in the response, most chain supports only `SIMPLE` and some(for example `stellar`) only `MEMO`: - `SIMPLE` - usual deposit with only deposit address. - `MEMO` - some chains will **REQUIRE** the `memo` together with `depositAddress` for swap to work. `depositMode` applies only to deposit transaction metadata. |
| `swapType` | "EXACT_INPUT" \\| "EXACT_OUTPUT" \\| "FLEX_INPUT" \\| "ANY_INPUT" | yes | How to interpret `amount` (and refunds) when performing the swap: - `EXACT_INPUT` — requests the output amount for an exact input.   - If deposit is less than `amountIn`, the deposit is refunded by deadline.   - If deposit is above than `amountIn`, the swap is processed and the excess is refunded to `refundTo` address after swap is complete. - `EXACT_OUTPUT` — requests the input amount for an exact output.   - The output amount (`amountOut`) is fixed; slippage is applied to the **input** side.   - The quote response includes `amountIn` (the proposed input with slippage tolerance baked in) and `minAmountIn` (the minimum input required).   - **Important**: `amountIn` will appear higher than `minAmountIn` by approximately your `slippageTolerance`. This is **not** price degradation—it is a buffer to ensure successful execution. Any input amount above what is actually needed for the swap is **refunded** to your `refundTo` address after the swap completes.   - If the deposit is above `amountIn`, the swap is processed and the excess is refunded to `refundTo` address after swap is complete.   - If the deposit is less than `minAmountIn`, the deposit is refunded by deadline. - `FLEX_INPUT` — a flexible input amount that allows for partial deposits and variable amounts.   - `slippage` applies both to `amountOut` and `amountIn` and defines an acceptable range (`minAmountIn` and `minAmountOut`).   - Any amount higher than `minAmountIn` is accepted and converted to the output asset as long as `minAmountOut` is met.   - The deposit must be at least `minAmountIn`, after applying the slippage constraint to the quoted amount. Deposits below `minAmountIn` are refunded if the total received by the deadline is below this amount.   - If deposits exceed the upper bound, the swap is still processed - `ANY_INPUT` — collects deposits and converts them to a destination asset. Used for fee aggregation and similar use cases. Only available for authorized partners. |
| `slippageTolerance` | number | yes | Slippage tolerance for the swap. This value is in basis points (1/100th of a percent), e.g. 100 for 1% slippage. |
| `originAsset` | string | yes | ID of the origin asset. |
| `depositType` | "ORIGIN_CHAIN" \\| "INTENTS" \\| "CONFIDENTIAL_INTENTS" | yes | Type of deposit address: - `ORIGIN_CHAIN` - deposit address on the origin chain. - `INTENTS` - the account ID within NEAR Intents to which you should transfer assets. - `CONFIDENTIAL_INTENTS` - the account ID within Confidential Intents to which assets are to be transferred. Fund the swap from a Confidential Intents account by submitting a signed transfer intent to the quote `depositAddress`. Direct token transfers are not supported. |
| `destinationAsset` | string | yes | ID of the destination asset. |
| `amount` | string | yes | Amount to swap as the base amount. It is interpreted as the input or output amount based on the `swapType` flag and is specified in the smallest unit of the currency (e.g., wei for ETH). Must be an integer string; decimal values like "0.01" are invalid—use base units (e.g. "10000000000000000" for 0.01 with 18 decimals). |
| `refundTo` | string | yes | Address used for refunds. |
| `refundType` | "ORIGIN_CHAIN" \\| "INTENTS" \\| "CONFIDENTIAL_INTENTS" | yes | Type of refund address: - `ORIGIN_CHAIN` - assets are refunded to the `refundTo` address on the origin chain. - `INTENTS` - assets are refunded to the `refundTo` Intents account. - `CONFIDENTIAL_INTENTS` - assets are refunded to the `refundTo` Confidential Intents account. On Confidential Intents, 1Click settles refunds via signed transfer intent rather than direct token transfer. |
| `recipient` | string | yes | Recipient address. The format must match `recipientType`. Destination routing metadata, when required, must be encoded according to the destination chain address format. |
| `connectedWallets` | string[] |  | Addresses of connected wallets. |
| `sessionId` | string |  | Unique client session identifier for 1Click. |
| `virtualChainRecipient` | string |  | EVM address of a transfer recipient in a virtual chain |
| `virtualChainRefundRecipient` | string |  | EVM address of a refund recipient in a virtual chain |
| `customRecipientMsg` | string |  | **HIGHLY EXPERIMENTAL** Message to pass to `ft_transfer_call` when withdrawing assets to NEAR. Otherwise, `ft_transfer` will be used. **WARNING**: Funds will be lost if used with non NEP-141 tokens, in case of insufficient `storage_deposit` or if the recipient does not implement `ft_on_transfer` method. |
| `recipientType` | "DESTINATION_CHAIN" \\| "INTENTS" \\| "CONFIDENTIAL_INTENTS" | yes | Type of recipient address: - `DESTINATION_CHAIN` - assets are transferred to the chain of `destinationAsset`. - `INTENTS` - assets are transferred to an account inside Intents. - `CONFIDENTIAL_INTENTS` - assets are transferred to the `recipient` account inside Confidential Intents. On Confidential Intents, 1Click settles swap output via signed transfer intent rather than direct token transfer. |
| `deadline` | string | yes | Timestamp in ISO format that identifies when the user refund begins if the swap isn't completed by then. It must exceed the time required for the deposit transaction to be mined. For example, Bitcoin may require around one hour depending on the fees paid. |
| `confidentiality` | "public" \\| "basic" \\| "advanced" |  | Confidentiality mode for this quote. PUBLIC is the default; BASIC or ADVANCED request Confidential Intents handling. |
| `simulate` | "STUCK" \\| "FAILED" |  | **Tidepool-only, testnet-only, optional.** Real 1Click has no such field; omit it and Tidepool behaves like 1Click. Simulates a swap outage after the deposit is detected. `STUCK`: the swap goes to `PROCESSING` and stays there until `deadline`, then the origin token is refunded to `refundTo` (`REFUNDED`, `refundReason: DEADLINE_PASSED`). `FAILED`: the swap goes to `PROCESSING`, then `FAILED`, and the deposit is refunded (`refundReason: SWAP_FAILED`, `refundedAmount` set). Other values return HTTP 400. Not supported with `ANY_INPUT`. The flag is stored with the quote and reported as `tidepool.simulate` in `/v0/status`. It reproduces what a client sees when 1Click is slow or down, not the cause. Remove it when you move to mainnet 1Click. |
| `referral` | string |  | Distribution channel / venue identifier (for example: ledger, trustwallet). Keep lowercase for consistency. |
| `rebates` | Rebate[] |  | Rebate distribution for this quote. Provide up to 3 confidential Intents recipients (for example, `rebate-recipient.near` on confidential Intents); each item defines a recipient and its percent share, and all shares must add up to 100. |
| `rebates[].[]recipient` | string | yes | Confidential Intents account identifier that receives this rebate share. Rebate delivery uses signed transfer intent on Confidential Intents; direct token transfers are not supported. |
| `rebates[].[]share` | number | yes | Rebate share for this recipient in percent. |
| `quoteWaitingTimeMs` | number |  | Time in milliseconds the user is willing to wait for a quote from the relay. **Defaults to 0ms delay if not specified, if you want to receive the fastest quote. |
| `appFees` | AppFee[] |  | List of recipients and their fees |
| `appFees[].[]recipient` | string | yes | Account ID within Intents to which this fee will be transferred |
| `appFees[].[]fee` | number | yes | Fee for this recipient as part of amountIn in basis points (1/100th of a percent), e.g. 100 for 1% fee |
| `insured` | boolean |  | Opt into an insured swap. When `true`, an additional 0.02% (2 basis points) insurance fee is charged on top of any other fees. |

### 401 Unauthorized - API key or JWT token is invalid

Tidepool does not return this: API keys and JWTs are optional on `/v0/quote`, and any `X-API-Key` / `Authorization: Bearer` value is accepted (it only selects the lower fee tier).
