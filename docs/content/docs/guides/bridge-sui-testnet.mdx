## Deposit model: per-quote addresses, no memo

Sui needs no memo, and 1Click itself gives Sui quotes a plain deposit address. Tidepool does the same: every Sui-origin quote gets its own `0x…` `depositAddress` (an ed25519 key derived from the quote id and the server master seed). Send the exact `amountIn` of the origin asset to it from any wallet:

- **SUI:** an ordinary transfer of SUI coins (`splitCoins` from gas, `transferObjects`).
- **USDC or USDT:** transfer `Coin<…>` objects of that test coin to the address. Do not send a different coin type: it is not credited.
- `depositMode` is `SIMPLE` (the default). `ANY_INPUT` deposits are accepted as on Solana, but an `ANY_INPUT` quote that pays out SUI is rejected.
- `POST /v0/deposit/submit` with `txHash` (the Sui transaction digest) and `depositAddress` is optional: the relayer watches the address and detects the deposit anyway.
- After the deposit is seen, the relayer **sweeps** the deposit address into the treasury with a sponsored transaction (the sender is the deposit address, the treasury pays the gas, both sign), then mints the NEP-141 on NEAR and credits it to the verifier. The sweep appears in the swap's `tidepool.explorer` list.

## The SUI cap (0.005 SUI)

Any swap with a SUI leg is rejected at **quote time** with a `400` if the SUI amount (input or output) exceeds `0.005 SUI` (5,000,000 MIST). It covers swaps, payouts and refunds. Why: the treasury is funded by the public Sui testnet faucet, which gives only a little SUI per request, so a small cap keeps one user from draining it. Also:

- A payout of SUI is paid from the treasury, so quotes answer `503` if the treasury cannot cover the payout plus gas.
- `ANY_INPUT` quotes that pay out SUI to a Sui address are rejected.
- USDC and USDT legs are not capped.
- Recipients and `refundTo` must be full `0x` + 64 hex addresses.

## 1. Get tokens

SUI: the public [Sui testnet faucet](https://faucet.sui.io) (the Tidepool faucet never drips SUI to wallets). USDC and USDT: Tidepool's faucet, no trustline or token account is needed on Sui.

```bash
curl -X POST https://www.usetidepool.tech/v0/faucet -H 'content-type: application/json' \
  -d '{"chain":"sui","address":"0xYourSuiAddress"}'
```

## 2. Sui → NEAR

```ts
const quote = await OneClickService.getQuote({
  dry: false, swapType: 'EXACT_INPUT', slippageTolerance: 100,
  originAsset: 'nep141:sui.tp-omft.testnet',
  destinationAsset: 'nep141:usdc.tidepool-sandbox.testnet',
  amount: '5000000',                        // 0.005 SUI in MIST
  depositType: 'ORIGIN_CHAIN',
  refundTo: '0xYourSuiAddress', refundType: 'ORIGIN_CHAIN',
  recipient: 'you.testnet', recipientType: 'DESTINATION_CHAIN',
  deadline: new Date(Date.now() + 30 * 60_000).toISOString(),
});
const { depositAddress, amountIn } = quote.quote;
// Transfer amountIn MIST of SUI to depositAddress, then (optional):
await OneClickService.submitDepositTx({ txHash: '<sui tx digest>', depositAddress });
// Poll GET /v0/status?depositAddress=...
```

Runnable: `RECIPIENT=you.testnet npm run sui-deposit` in [tidepool-examples](https://github.com/Watchmeecryt/tidepool-examples) (it needs `SUI_SECRET_KEY`, a testnet key with a little SUI, and prints the Suiscan links). The example builds the transaction offline because `@mysten/sui` 1.x cannot resolve one over gRPC; the public Sui JSON-RPC is deprecated, so Tidepool itself talks to the testnet fullnode over gRPC.

## 3. NEAR → Sui

Quote with a Sui `destinationAsset`, `recipient: '0xYourSuiAddress'` and `recipientType: 'DESTINATION_CHAIN'`, then deposit on NEAR as usual. The verifier `ft_withdraw`s the bridged token to the relayer, which pays out on Sui from the treasury: SUI is split from the treasury's gas coins, USDC and USDT are **minted** straight to your address with the `TreasuryCap`. Payouts are signed first and the signed transaction (with a deterministic digest) is recorded before it is sent, so a crash or retry re-submits the same bytes and never pays twice.

## Refunds

Same reasons as every route (`DEADLINE_PASSED`, `PARTIAL_DEPOSIT`, …). A refund with `refundType: "ORIGIN_CHAIN"` is paid from the treasury to `refundTo` on Sui in the asset you sent (a SUI refund is a transfer; a USDC or USDT refund is a mint).

## Limits

- **Testnet resets.** Sui testnet is wiped from time to time. After a reset the package, coins and balances are gone and the route has to be bootstrapped again.
- **Coin objects only.** Sui testnet faucet funds can land in an address balance rather than as Coin objects; the relayer only spends Coin objects, so the treasury keeps a large SUI coin for gas and payouts.
- **One treasury-signed transaction at a time.** Payouts and sweeps share the treasury gas coin, so they are serialized.
- **Faucet.** The USDC/USDT faucet spends treasury gas, so it has a global daily cap (`SUI_FAUCET_DAILY_MAX`, default 300 drips per day) on top of the usual per-address and per-IP limits.
- **Unreachable destinations.** If a payout keeps failing on-chain, the swap stays in `PROCESSING` with a note and needs operator attention.
- **Fullnode.** The relayer uses the public testnet fullnode (override: `SUI_GRPC_URL`); congestion or rate limits can delay a swap.

## Mapping to mainnet 1Click

Same request and response fields, `blockchain: "sui"`, a plain `depositAddress` and no memo. Mainnet lists Sui assets as `nep141:sui….omft.near` ids with the same keccak256 rule. Take the Sui asset ids from `GET /v0/tokens` of the environment you are calling. Mainnet has no 0.005 SUI cap and uses real Sui addresses. 1Click lists no Sui USDT on mainnet; the Tidepool USDT exists so testnet has the same pair as the other chains.
