The Tidepool Agent API is a free NEAR **testnet** implementation of the NEAR Intents Agent API: an owner creates a policy-bound agent wallet, issues the agent a revocable grant, and the agent then swaps, transfers, withdraws and deposits inside that policy. It lives on the same host as the `/v0` 1Click sandbox, under `/v1`, and works with the official `@near-intents-agent-api/sdk` by changing only its `baseUrl`.

Testnet only. Tokens have no value. Owners are NEAR testnet accounts (an implicit account is just an ed25519 key, so no wallet or on-chain account is needed).

## 1. Get a free key (no sign-up, no human)

```bash
curl -s -X POST https://www.usetidepool.tech/v1/keys -H 'content-type: application/json' -d '{"name":"my-agent"}'
```

The response contains `api_key` (`naa_...`, shown once). Send it as `Authorization: Bearer <key>` or `x-api-key`. Limits: 600 requests per minute per key, 25 agents per key (`GET /v1/quotas` reports it as `daily_agents`; Tidepool agents are never deleted, so in practice a key holds at most 25 agents in total and the 26th `agent_create` fails with 429 `quota_exceeded`: get another free key), 5 new keys per IP per 24 hours. Keys do not expire, so reuse yours.

```bash
export TP=https://www.usetidepool.tech/v1
export KEY=naa_...                       # from the response above
curl -s $TP/whoami -H "authorization: Bearer $KEY"
curl -s $TP/tokens -H "authorization: Bearer $KEY"     # asset ids for swaps, limits and policies
curl -s $TP/network
```

## 2. Run the whole flow in one command

The reference script gets a key, creates an owner and an agent, issues a grant, funds the agent from the faucet, then swaps (dry and real), transfers, withdraws, reads status and history, and checks that policy violations are rejected. It needs Node 20 or newer and no dependencies. It prints PASS or FAIL per step.

```bash
curl -s https://www.usetidepool.tech/v1/e2e.js -o agent-api-e2e.mjs && node agent-api-e2e.mjs https://www.usetidepool.tech
```

## 3. The model

1. **Owner intents** (signed with the owner key, NEP-413 / ed25519): `agent_create`, `grant_issue`, `grant_revoke`, `policy_update`, `agent_freeze`, `agent_unfreeze`. Call `POST /v1/generate-intent`, sign `intent.payload` with the owner key, send it to `POST /v1/submit-intent`, then poll `GET /v1/status?correlation_id=...`.
2. **Agent actions** (no owner signature): `swap`, `transfer`, `withdraw`, `deposit` (deposit needs no grant token). They need the API key, an `x-grant-token` (an `ngt_` token whose sha256 hex the owner registered with `grant_issue`) and an `Idempotency-Key`. They return 202 with a `correlation_id`; poll `GET /v1/status`.
3. **Dry runs**: `POST /v1/agents/ID/swap` or `/withdraw` with `"dry": true` needs only the API key. It returns a quote and `warnings` and never refuses for policy or balance reasons.

Owner account: for an implicit account (64 hex characters) the `account_id` must equal the hex of the ed25519 public key; for a named account the key must be a full-access key of that account.

## Endpoints

| Method and path | Purpose |
| --- | --- |
| `POST /v1/keys` | Free self-serve key (no auth) |
| `GET /v1/whoami`, `/v1/quotas`, `/v1/network`, `/v1/tokens` | Identity, limits, network, assets |
| `POST /v1/generate-intent`, `POST /v1/submit-intent` | Owner intents |
| `GET /v1/status?correlation_id=...&wait_ms=30000` | Long-poll any intent or action |
| `GET /v1/agents`, `/v1/agents/ID`, `/wallet`, `/balances`, `/policy`, `/policy/history`, `/grants`, `/history` | Read agents |
| `POST /v1/agents/ID/swap`, `/transfer`, `/withdraw`, `/deposit` | Agent actions |
| `GET /v1/openapi.json`, `GET /v1/e2e.js` | Spec and reference script |

**Supported:** owners that are NEAR testnet accounts; `agent_create`, `grant_issue`, `grant_revoke`, `policy_update`, `freeze` and `unfreeze` intents; swap (with `dry`), transfer, deposit (testnet faucet or deposit address); withdraw to NEAR accounts (`chain` `near`, NEAR-native tokens) and, for the bridged tokens, to every testnet that Tidepool's `/v0` already pays out on: Base Sepolia, Arbitrum Sepolia and Ethereum Sepolia (`base`, `arb`, `eth`), Solana devnet (`sol`), Stellar testnet (`stellar`), Sui testnet (`sui`), XRP Ledger testnet (`xrp`), Bitcoin testnet4 (`btc`) and Zcash testnet (`zec`, when enabled). Which of them are live is whatever `GET /v1/tokens` lists. The status carries `destination_chain` and `destination_tx_hash`, and the same per-payout caps and minimums as `/v0` apply to native ETH (0.01 ETH, on `eth`, `base` and `arb`), SOL, XLM, SUI, XRP, BTC and ZEC. Also: balances, history, long-poll status, idempotency keys, policy enforcement, and `GET /v1/releases`, `/v1/releases/latest`, `/v1/releases/{version}` (the SDK's `getLatestRelease`).

**Not supported:** a memo on withdrawals to chains other than NEAR (Tidepool's payout paths carry none); confidential mode (400 `unsupported_feature`); passkey and EVM owners and other owner intent types (400 `unsupported_owner_type`, `unsupported_intent_type`); shielding, native-chain wallets, approvals, containment, scheduled executions, per-agent releases and proofs (HTTP 501 `not_supported`). Chains `/v0` cannot pay out on are not offered.

## Policy model

A policy is stored per agent and enforced by the API before any action runs. Changes apply immediately and are versioned (send `expected_revision` with `policy_update`). Check order: frozen, action, asset, destination, per-transaction limit, USD budget, cumulative limits, actions per hour.

```json
{
  "frozen": false,
  "actions": ["swap", "transfer", "withdraw"],
  "assets": "any",
  "limits": { "per_transaction": { "ASSET_ID": "50000000" }, "daily": {}, "hourly": {}, "monthly": {} },
  "max_actions_per_hour": null,
  "destinations": { "mode": "any", "list": [] },
  "budget": { "daily_usd": "100", "weekly_usd": null, "monthly_usd": null }
}
```

`destinations.mode` is `any`, `only` (send only to the listed destinations) or `except` (send anywhere but them); `allowlist` and `denylist` are rejected with 400 `validation_failed`. List entries are objects, not strings: `{ "action": "transfer", "address": "shop.testnet", "confidential": false }` or `{ "action": "withdraw", "chain": "near", "address": "alice.testnet", "memo": null }`.

Violations return HTTP 403 with `layer: "policy"` and a code such as `policy_action_denied`, `policy_asset_denied`, `policy_destination_denied`, `policy_transaction_limit_exceeded`, `policy_budget_exceeded` or `policy_action_limit_exceeded`. A frozen agent returns 409 `wallet_frozen`; a revoked grant returns 403 `grant_revoked`.

## Faucet deposits

`POST /v1/agents/{id}/deposit` with `{"origin_asset": "...", "testnet_faucet": true}` drips the default test tokens into the agent wallet. It allows one drip per agent wallet per hour and a few per IP per hour. When it is rate-limited the call answers **429 `rate_limited`** right away (with `Retry-After`) and no execution is created, so check the HTTP status, not just for a `correlation_id`. A 202 means the drip was accepted: poll `GET /v1/status` until `SUCCESS` before spending.

## Idempotency and errors

Repeating an action with the same `Idempotency-Key` and body replays the original execution; the same key with a different body returns 409 `idempotency_conflict`. Concurrent actions on one agent return 409 `wallet_busy` (retryable). Errors are JSON:API: `{"errors":[{"status","code","layer","title","detail","source":{"pointer"},"meta":{"retryable"}}],"meta":{"request_id"}}`.

## Official SDK

```ts
import { createAgentApi } from '@near-intents-agent-api/sdk';
const api = createAgentApi({ baseUrl: 'https://www.usetidepool.tech', apiKey: process.env.KEY }); // the SDK appends /v1
const tokens = await api.getTokens();
```

The SDK needs Node 24 or newer. Use the Tidepool origin as `baseUrl`, and an `naa_` key from `POST /v1/keys`.
