Happy-path swaps are the easy part. This guide covers what your integration has to handle when a deposit goes wrong. Each case below was run against `https://www.usetidepool.tech` on NEAR testnet. The status JSON on this page is the real response from those runs, and every transaction is linked on NearBlocks.

<Callout title="Same semantics as 1Click">
Tidepool uses the 1Click status values (`PENDING_DEPOSIT`, `KNOWN_DEPOSIT_TX`, `INCOMPLETE_DEPOSIT`, `PROCESSING`, `SUCCESS`, `REFUNDED`, `FAILED`) and the same `swapDetails` fields (`depositedAmount`, `refundedAmount`, `refundReason`). Code that handles these cases here should handle them the same way against 1Click. Only the extra `tidepool` object is Tidepool-specific, and 1Click clients can ignore it.
</Callout>

| Case | What you do | What you get |
| --- | --- | --- |
| [Partial deposit](#partial-deposit) | Deposit less than `minAmountIn` | `INCOMPLETE_DEPOSIT`, then `REFUNDED` with `refundReason: PARTIAL_DEPOSIT` at the deadline |
| [Late deposit](#late-deposit) | Deposit the full amount after `deadline` | `REFUNDED` with `refundReason: DEADLINE_PASSED` |
| [Overpay](#overpay) | Deposit more than `amountIn` | `SUCCESS`, with the excess in `swapDetails.refundedAmount` |
| [Stuck or failed swap (simulated outage)](#stuck-or-failed-swap-simulated-outage) | Add `simulate: "STUCK"` or `"FAILED"` to the quote (Tidepool-only, testnet) | `STUCK`: `PROCESSING`, then `REFUNDED` (`DEADLINE_PASSED`) at the deadline. `FAILED`: `PROCESSING`, then `FAILED` (`SWAP_FAILED`), deposit refunded |
| [API errors](#api-errors) | A bad deadline, or an unknown deposit address | HTTP 400 or 404 before any funds move |

The refund always returns the **origin token** to `refundTo`. See [Refunds](/docs/concepts/refunds) for every refund reason and [Status lifecycle](/docs/concepts/status-lifecycle) for the state machine.

## Run it yourself

`examples/failure-cases.mjs` (in the repo, and in full below) runs every case. It tops up your intents balance from the faucet, deposits with a signed intents `transfer`, and prints the full `/v0/status` JSON on every status change.

```bash
npm install near-api-js@5 bs58@6   # Node 20+; save the script below as failure-cases.mjs
# Uses a throwaway testnet account by default, or set NEAR_ACCOUNT_ID + NEAR_PRIVATE_KEY.
TIDEPOOL_URL=https://www.usetidepool.tech node failure-cases.mjs all       # about 5 minutes
node failure-cases.mjs partial   # or: expired | overpay | stuck | failed | errors
node failure-cases.mjs all --json run.json   # also save every status response
```

```js title="failure-cases.mjs"
// Tidepool failure cases on NEAR testnet: partial deposit, expired quote, overpay, simulated stuck/failed swaps, and API errors.
//
//   TIDEPOOL_URL=https://www.usetidepool.tech node failure-cases.mjs [partial|expired|overpay|stuck|failed|errors|all]
//
// Account: NEAR_ACCOUNT_ID + NEAR_PRIVATE_KEY, or a throwaway testnet account kept in ./.example-account.json
// (same as swap.mjs). Deposits are INTENTS transfers from your verifier balance; the faucet tops it up.
// Every /v0/status change is printed as full JSON. Keys are never printed. Pass --json out.json to save a log.
import fs from 'node:fs';
import crypto from 'node:crypto';
import { connect, keyStores, KeyPair } from 'near-api-js';
import bs58 from 'bs58';

const API = process.env.TIDEPOOL_URL || 'https://www.usetidepool.tech';
const RPC = process.env.NEAR_RPC || 'https://test.rpc.fastnear.com';
const CASE = process.argv.slice(2).find(a => !a.startsWith('--') && !a.endsWith('.json')) || 'all';
const OUT = process.argv.includes('--json') ? process.argv[process.argv.indexOf('--json') + 1] : null;
const log = [];
const say = (...a) => console.log(new Date().toISOString().slice(11, 19), ...a);
const sleep = ms => new Promise(r => setTimeout(r, ms));
const call = async (method, path, body) => {
  const r = await fetch(API + path, { method, headers: { 'content-type': 'application/json', 'x-api-key': process.env.TIDEPOOL_KEY || 'dummy.jwt.token' }, body: body && JSON.stringify(body) });
  return { status: r.status, body: await r.json().catch(() => null) };
};
const api = async (m, p, b) => { const r = await call(m, p, b); if (r.status >= 400) throw new Error(`${m} ${p} ${r.status}: ${r.body?.message}`); return r.body; };

// ---- account ----
const keyStore = new keyStores.InMemoryKeyStore();
let accountId = process.env.NEAR_ACCOUNT_ID;
if (accountId) await keyStore.setKey('testnet', accountId, KeyPair.fromString(process.env.NEAR_PRIVATE_KEY));
else {
  const f = new URL('./.example-account.json', import.meta.url);
  if (!fs.existsSync(f)) {
    const kp = KeyPair.fromRandom('ed25519'); const id = `tidepool-try-${crypto.randomBytes(4).toString('hex')}.testnet`;
    const r = await fetch('https://helper.nearprotocol.com/account', { method: 'POST', headers: { 'content-type': 'application/json' }, body: JSON.stringify({ newAccountId: id, newAccountPublicKey: kp.getPublicKey().toString() }) });
    if (!r.ok) throw new Error('could not create a testnet account: ' + r.status);
    fs.writeFileSync(f, JSON.stringify({ accountId: id, privateKey: kp.toString() }), { mode: 0o600 });
  }
  const k = JSON.parse(fs.readFileSync(f)); accountId = k.accountId; await keyStore.setKey('testnet', accountId, KeyPair.fromString(k.privateKey));
}
const near = await connect({ networkId: 'testnet', nodeUrl: RPC, keyStore });
const me = await near.account(accountId);
const tokens = await api('GET', '/v0/tokens');
const USDC = tokens.find(t => t.symbol === 'USDC'), WNEAR = tokens.find(t => t.symbol === 'wNEAR');
const verifier = (await api('GET', '/v0/health')).verifier;
say('account', accountId, 'verifier', verifier);
try { await api('POST', '/v0/faucet', { accountId, mode: 'intents' }); say('faucet: topped up intents balance'); } catch (e) { say('faucet skipped:', e.message); }

// ---- helpers ----
const quote = (deadlineMs, extra = {}) => api('POST', '/v0/quote', {
  dry: false, swapType: 'EXACT_INPUT', slippageTolerance: 100, originAsset: USDC.assetId, destinationAsset: WNEAR.assetId,
  amount: '5000000', depositType: 'INTENTS', refundTo: accountId, refundType: 'INTENTS', recipient: accountId, recipientType: 'INTENTS',
  deadline: new Date(Date.now() + deadlineMs).toISOString(), ...extra,
});
async function deposit(depositAddress, amount) {
  const kp = await keyStore.getKey('testnet', accountId); const pk = kp.getPublicKey().toString();
  if (!(await me.viewFunction({ contractId: verifier, methodName: 'has_public_key', args: { account_id: accountId, public_key: pk } })))
    await me.functionCall({ contractId: verifier, methodName: 'add_public_key', args: { public_key: pk }, attachedDeposit: 1n, gas: 30_000_000_000_000n });
  const nonce = crypto.randomBytes(32); if (nonce[0] === 0x56 && nonce[1] === 0x28) nonce[0] ^= 0xff;
  const message = JSON.stringify({ signer_id: accountId, verifying_contract: verifier, deadline: new Date(Date.now() + 120_000).toISOString(), nonce: nonce.toString('base64'), intents: [{ intent: 'transfer', receiver_id: depositAddress, tokens: { [USDC.assetId]: amount } }] });
  const s = x => { const b = Buffer.from(x); const l = Buffer.alloc(4); l.writeUInt32LE(b.length); return Buffer.concat([l, b]); };
  const tag = Buffer.alloc(4); tag.writeUInt32LE(2 ** 31 + 413);
  const hash = crypto.createHash('sha256').update(Buffer.concat([tag, s(message), nonce, s(verifier), Buffer.from([0])])).digest();
  const signed = { standard: 'nep413', payload: { message, nonce: nonce.toString('base64'), recipient: verifier }, public_key: pk, signature: 'ed25519:' + bs58.encode(Buffer.from(kp.sign(hash).signature)) };
  const out = await me.functionCall({ contractId: verifier, methodName: 'execute_intents', args: { signed: [signed] }, gas: 100_000_000_000_000n });
  const txHash = out.transaction.hash;
  say(`deposited ${amount} tx https://testnet.nearblocks.io/txns/${txHash}`);
  await api('POST', '/v0/deposit/submit', { txHash, depositAddress, nearSenderAccount: accountId });
  return txHash;
}
// Poll /v0/status, printing the full JSON on every status change, until a final status (or timeout).
async function watch(name, depositAddress, timeoutMs = 240_000) {
  let last; const t0 = Date.now();
  while (Date.now() - t0 < timeoutMs) {
    const st = await api('GET', `/v0/status?depositAddress=${depositAddress}`);
    if (st.status !== last) { last = st.status; say(`[${name}] status ${st.status}`); console.log(JSON.stringify(st, null, 2)); log.push({ case: name, at: new Date().toISOString(), status: st }); }
    if (['SUCCESS', 'REFUNDED', 'FAILED'].includes(st.status)) return st;
    await sleep(3000);
  }
  throw new Error(`${name}: no final status after ${timeoutMs / 1000}s (last ${last})`);
}

// ---- cases ----
const cases = {
  // Deposit half of amountIn. Status sits at INCOMPLETE_DEPOSIT, then REFUNDED (PARTIAL_DEPOSIT) once the deadline passes.
  async partial() {
    const q = await quote(75_000); const { depositAddress, amountIn, minAmountIn, deadline } = q.quote;
    say('[partial] quote', depositAddress, 'amountIn', amountIn, 'minAmountIn', minAmountIn, 'deadline', deadline);
    const tx = await deposit(depositAddress, (BigInt(amountIn) / 2n).toString());
    const st = await watch('partial', depositAddress); log.push({ case: 'partial', depositTx: tx, depositAddress }); return st;
  },
  // Quote with a 65 s deadline, wait it out, then deposit the full amount: REFUNDED (DEADLINE_PASSED).
  async expired() {
    const q = await quote(65_000); const { depositAddress, amountIn, deadline } = q.quote;
    say('[expired] quote', depositAddress, 'deadline', deadline, '- waiting for it to pass');
    await watch('expired', depositAddress, 1).catch(() => {});
    await sleep(new Date(deadline).getTime() - Date.now() + 5_000);
    const tx = await deposit(depositAddress, amountIn);
    const st = await watch('expired', depositAddress); log.push({ case: 'expired', depositTx: tx, depositAddress }); return st;
  },
  // Deposit 1.5x amountIn: SUCCESS, and the excess comes back as swapDetails.refundedAmount.
  async overpay() {
    const q = await quote(600_000); const { depositAddress, amountIn } = q.quote;
    const tx = await deposit(depositAddress, (BigInt(amountIn) * 3n / 2n).toString());
    const st = await watch('overpay', depositAddress); log.push({ case: 'overpay', depositTx: tx, depositAddress }); return st;
  },
  // Tidepool-only `simulate: "STUCK"`: the deposit is seen, the swap goes PROCESSING and never settles, then it is
  // REFUNDED (DEADLINE_PASSED) at the quote deadline. Reproduces a client's view of a slow or down 1Click. Remove `simulate` on mainnet.
  async stuck() {
    const q = await quote(65_000, { simulate: 'STUCK' }); const { depositAddress, amountIn, deadline } = q.quote;
    say('[stuck] quote', depositAddress, 'deadline', deadline, 'tidepool', JSON.stringify(q.tidepool));
    const tx = await deposit(depositAddress, amountIn);
    const st = await watch('stuck', depositAddress); log.push({ case: 'stuck', depositTx: tx, depositAddress }); return st;
  },
  // Tidepool-only `simulate: "FAILED"`: PROCESSING, then FAILED, and the deposit is refunded (SWAP_FAILED).
  async failed() {
    const q = await quote(600_000, { simulate: 'FAILED' }); const { depositAddress, amountIn } = q.quote;
    say('[failed] quote', depositAddress, 'tidepool', JSON.stringify(q.tidepool));
    const tx = await deposit(depositAddress, amountIn);
    const st = await watch('failed', depositAddress); log.push({ case: 'failed', depositTx: tx, depositAddress }); return st;
  },
  // API errors you should handle before any funds move.
  async errors() {
    const show = async (label, r) => { say(`[errors] ${label}: HTTP ${(r = await r).status}`, JSON.stringify(r.body)); log.push({ case: 'errors', label, http: r.status, body: r.body }); };
    const body = { dry: false, swapType: 'EXACT_INPUT', slippageTolerance: 100, originAsset: USDC.assetId, destinationAsset: WNEAR.assetId, amount: '5000000', depositType: 'INTENTS', refundTo: accountId, refundType: 'INTENTS', recipient: accountId, recipientType: 'INTENTS' };
    await show('deadline 30 s ahead', call('POST', '/v0/quote', { ...body, deadline: new Date(Date.now() + 30_000).toISOString() }));
    await show('deadline in the past', call('POST', '/v0/quote', { ...body, deadline: new Date(Date.now() - 60_000).toISOString() }));
    await show('deadline not a date', call('POST', '/v0/quote', { ...body, deadline: 'tomorrow' }));
    await show('simulate not STUCK or FAILED', call('POST', '/v0/quote', { ...body, deadline: new Date(Date.now() + 600_000).toISOString(), simulate: 'BOOM' }));
    await show('deadline 2 days ahead', call('POST', '/v0/quote', { ...body, deadline: new Date(Date.now() + 48 * 3600_000).toISOString() }));
    const bogus = crypto.randomBytes(32).toString('hex');
    await show('status of an unknown deposit address', call('GET', `/v0/status?depositAddress=${bogus}`));
    await show('submit a deposit for an unknown address', call('POST', '/v0/deposit/submit', { txHash: '8HAgViUuMBZ6bMSU3g6tMx5df6FFpevyHkQTLLcWqZzK', depositAddress: bogus }));
  },
};
const run = CASE === 'all' ? ['errors', 'overpay', 'partial', 'expired', 'stuck', 'failed'] : [CASE];
for (const c of run) {
  const st = await cases[c]();
  if (st) { const d = st.swapDetails; say(`[${c}] final ${st.status}`, JSON.stringify({ refundReason: d.refundReason, refundedAmount: d.refundedAmountFormatted, amountOut: d.amountOutFormatted })); for (const t of st.tidepool?.explorer || []) say('  ', t.label, t.url); }
}
if (OUT) fs.writeFileSync(OUT, JSON.stringify(log, null, 2));
```

Live quotes need a deadline at least 60 seconds ahead, so the script uses 65–75 second deadlines for the cases that wait on the deadline. Every run below quotes 5 USDC → wNEAR (`EXACT_INPUT`, `INTENTS` in and out, `refundType: INTENTS`).

## Stuck or failed swap (simulated outage)

<Callout type="warn" title="Testnet only. Remove `simulate` before you go to mainnet">
`simulate` is a Tidepool-specific field. Real 1Click has no such field, so remove it when you move to mainnet 1Click. Tidepool ignores the field when you omit it, and rejects any value other than `STUCK` or `FAILED` with a 400.
</Callout>

This case reproduces **what your client sees when 1Click is slow or down**: a deposit that is detected but never settles, or a swap that ends in `FAILED`. It does not reproduce the cause. Whatever goes wrong on a real outage happens inside NEAR's own infrastructure, which Tidepool does not simulate. Use it to test your polling timeouts, your "taking longer than expected" UI, and your handling of `REFUNDED` and `FAILED`.

Add `"simulate": "STUCK"` or `"simulate": "FAILED"` to a normal `POST /v0/quote` body:

```bash
curl -s -X POST https://www.usetidepool.tech/v0/quote \
  -H 'content-type: application/json' -H 'x-api-key: <your key>' \
  -d '{
    "dry": false,
    "swapType": "EXACT_INPUT",
    "slippageTolerance": 100,
    "originAsset": "nep141:usdc.tidepool-sandbox.testnet",
    "destinationAsset": "nep141:wnear.tidepool-sandbox.testnet",
    "amount": "5000000",
    "depositType": "INTENTS",
    "refundTo": "alice.testnet",
    "refundType": "INTENTS",
    "recipient": "alice.testnet",
    "recipientType": "INTENTS",
    "deadline": "<ISO 8601 time 65 s to 24 h ahead>",
    "simulate": "STUCK"
  }'
```

The flag is stored with the quote, so `/v0/status` stays consistent across server restarts. It is exposed only in the Tidepool-specific `tidepool` object (`tidepool.simulate`, plus an explanatory `tidepool.note`). The status value and the `swapDetails` fields are the plain 1Click ones. The simulation starts once the deposit is detected and is at least `minAmountIn`. An underpaid or late deposit is handled as in [Partial deposit](#partial-deposit) and [Late deposit](#late-deposit).

| `simulate` | After the deposit | Final status | `refundReason` |
| --- | --- | --- | --- |
| `STUCK` | `PROCESSING`, never settles, until the quote `deadline` | `REFUNDED` | `DEADLINE_PASSED` |
| `FAILED` | `PROCESSING`, then `FAILED` about 10 s later | `FAILED`, deposit refunded | `SWAP_FAILED` |

No new refund reason was added. `STUCK` reuses `DEADLINE_PASSED`, the existing reason for a deposit that was not swapped before the deadline, so code that branches on the known values keeps working. `FAILED` uses `SWAP_FAILED`. Normal Tidepool `FAILED` is only used when a refund itself cannot be completed, so for the simulation Tidepool also returns the origin token to `refundTo` and fills in `refundedAmount` and `refundReason`. Treat it as an outage you can recover from by re-quoting, and don't depend on that refund on mainnet: check `swapDetails.refundedAmount` rather than assuming one.

An invalid value is rejected with the usual helpful 400 (`message`, `hint`, `field`, `docs`, `exampleRequest`). This is the real response for `"simulate": "stuck"` (lowercase):

## API errors

These requests are rejected before any funds move. The response bodies below are real.

| Request | HTTP | Body |
| --- | --- | --- |
| `POST /v0/quote`, `dry: false`, deadline 30 s ahead | 400 | `{"message":"deadline must be at least 60 seconds in the future"}` |
| `POST /v0/quote`, `dry: false`, deadline in the past | 400 | `{"message":"deadline must be at least 60 seconds in the future"}` |
| `POST /v0/quote`, `deadline: "tomorrow"` | 400 | `{"message":"deadline must be an ISO 8601 date"}` |
| `POST /v0/quote`, `dry: false`, deadline 48 h ahead | 400 | `{"message":"deadline must be within 24 hours"}` |
| `POST /v0/quote` with `simulate: "stuck"` (or any value other than `STUCK`/`FAILED`) | 400 | `{"message":"simulate \"stuck\" is not supported (supported: STUCK, FAILED). Did you mean STUCK?", ...}` plus `hint`, `field`, `docs`, `exampleRequest` |
| `GET /v0/status?depositAddress=<unknown>` | 404 | `{"message":"Deposit address not found"}` |
| `POST /v0/deposit/submit` with an unknown `depositAddress` | 404 | `{"message":"Unknown depositAddress"}` |

Dry quotes (`dry: true`) skip the deadline window checks, because nothing is reserved.

<Callout type="warn" title="Never send funds to an address the API doesn't know">
A 404 from `/v0/status` means Tidepool never issued that deposit address. Funds sent there are not watched and will not be refunded automatically. Always deposit to `quote.depositAddress` from a live quote you received yourself.
</Callout>

## Integration tips

- **Poll `/v0/status`** every 2–5 s after you deposit, until the status is `SUCCESS`, `REFUNDED` or `FAILED`. `KNOWN_DEPOSIT_TX`, `INCOMPLETE_DEPOSIT` and `PROCESSING` are not final. Calling `/v0/deposit/submit` with your tx hash makes detection faster, but it is optional.
- **Treat `REFUNDED` as a normal outcome.** Branch on `swapDetails.refundReason`. For `PARTIAL_DEPOSIT` and `DEADLINE_PASSED`, ask the user for a fresh quote. For `SLIPPAGE_EXCEEDED` and `PRICE_MOVED`, re-quote, perhaps with more slippage. Show `refundedAmountFormatted` and the refund link from `destinationChainTxHashes`.
- **Check `refundedAmount` on `SUCCESS` as well.** It is non-zero when the user overpaid. That money is back in their `refundTo` balance and does not need a support ticket.
- **Show `INCOMPLETE_DEPOSIT` to the user.** Show `depositedAmount` against `minAmountIn`, with a countdown to `deadline`, so they can top up in time.
- **Pick deadlines that fit the deposit.** Live quotes need 60 s to 24 h. Allow for wallet confirmation and block time: 5–30 minutes suits interactive flows. Never reuse an expired deposit address. Get a new quote instead.
- **Make it idempotent.** One live quote is one deposit address is one swap. Key your records by `depositAddress` (or `correlationId`). Retrying `/v0/deposit/submit` or polling `/v0/status` is safe. Don't create a new quote on a retry, or you end up with two addresses for one payment.
- **Handle `FAILED`** (rare) as "contact support". On 1Click it means the swap could not complete. Tidepool uses it for a refund that could not be completed, and for `simulate: "FAILED"`, where the deposit is refunded with `refundReason: SWAP_FAILED`. Log `correlationId` and `tidepool.note`.
- **Time out on `PROCESSING`.** A swap that stays in `PROCESSING` for longer than `timeEstimate` plus a margin is a slow or down 1Click as far as your user can tell. Show "taking longer than expected", keep polling until the `deadline`, and expect `REFUNDED`. Test it with `simulate: "STUCK"`.
