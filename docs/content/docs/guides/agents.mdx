Tidepool is built to be read and used by coding agents and autonomous agents.

## Files for agents

- [`/llms.txt`](/llms.txt): an index of every page with a one-line summary.
- [`/llms-full.txt`](/llms-full.txt): every page in one plain-text file.
- [`/AGENTS.md`](/AGENTS.md): rules of the road for agents that call the API.
- [`/openapi.json`](/openapi.json): the machine-readable API.
- Any docs page as Markdown: add `.md` to its URL, for example [`/docs/quickstart.md`](/docs/quickstart.md).

## One-call demo

Reviewing Tidepool, or checking that your agent can reach it? One request runs the whole 1Click flow on testnet. No clone, no key, no account:

```bash
curl -X POST https://www.usetidepool.tech/v0/demo/run
```

Do this, then you see this: the server uses a funded testnet demo account (its key stays on the server and is never returned) and runs a real swap and a real LIMIT order. It takes roughly 30 to 90 seconds, so set your client timeout to 180 seconds or more. The response is a JSON step log with `ok: true` and a list of NearBlocks `explorerLinks` to the real transactions. Each entry in `steps` holds the exact public request (method, URL, headers, body) and the real response:

| Flow | What runs |
| --- | --- |
| `swap` | `GET /v0/tokens`, dry quote, live quote, `generate-intent`, signed `submit-intent`, `deposit/submit`, poll `/v0/status` until `SUCCESS`, `authenticate`, balances, history. 1 USDC to USDT. |
| `order` | `POST /v0/orders` (LIMIT, SELL 1 USDC at 1.5), fund it, read it, cancel it, read the refund. |
| `all` (default) | Both. |

```bash
curl -X POST https://www.usetidepool.tech/v0/demo/run -H 'content-type: application/json' -d '{"flow":"swap"}'
```

Limits: amounts are fixed at 1 USDC, 3 runs per hour per IP, 20 per hour in total, one run at a time, 150 second timeout. The server refuses to run when the demo account is low on test funds. Details: [`POST /v0/demo/run`](/docs/api-reference/tidepool-demo-run). Tidepool extension, testnet only.

## A full swap from a script

Want to run it yourself with your own account? The public [tidepool-examples](https://github.com/Watchmeecryt/tidepool-examples) repo ships `npm run first-swap`. It uses a fresh testnet account, so it needs no setup beyond Node 20:

```bash
git clone https://github.com/Watchmeecryt/tidepool-examples && cd tidepool-examples && npm install
npm run first-swap              # faucet → quote → deposit → status → SUCCESS
npm run failure-cases partial   # deposit too little, wait for REFUNDED
```

What it does:

1. Creates a throwaway testnet account through the public testnet helper.
2. Calls `POST /v0/faucet` with `mode: "intents"`.
3. Calls `POST /v0/quote` with `dry: false` and `depositType: "INTENTS"`.
4. Deposits with a signed NEP-413 `transfer` intent to the deposit address. The script submits it with `execute_intents` from its own account, so it pays its own gas.
5. Calls `POST /v0/deposit/submit`, then polls `GET /v0/status` until `SUCCESS` or `REFUNDED`.

## Rules for agents

- Always get a dry quote first and check `amountOut` and `minAmountOut` before going live.
- Deposit exactly `quote.amountIn`. Under `minAmountIn` waits for more until the deadline, then refunds.
- Poll `/v0/status` every 2 to 5 seconds. Stop on `SUCCESS`, `REFUNDED` or `FAILED`.
- Faucet: one drip per account and mode per hour. Do not loop on it.
- Never send real assets. Tidepool is testnet only.
